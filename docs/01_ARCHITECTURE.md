# Architecture

## Overview

Options Forecast & Backtest is a local-first platform for running deterministic backtests on financial data and (eventually) ML-driven forecasts.

### Module Layout

```
api/          → FastAPI backend (entrypoint: api.main:app)
backtest/     → Core backtest engine, broker, metrics, strategies
common/       → Shared schemas, I/O, caching, time utilities
ml/           → ML model definitions and training utilities
pipelines/    → Data ingestion, feature engineering, training, prediction
dashboard/    → Streamlit dashboard (secondary UI)
web/          → Static HTML/JS/CSS UI served by FastAPI
tests/        → Unit and integration tests
data/         → Local artifact store (raw, processed, models, predictions, backtests)
docs/         → Project documentation
```

## Phase 0 — Boot & Failure Map (2026-02-28)

### Findings

**Backend entrypoint**: `api/main.py` → `create_app()` → `app = create_app()`
- Invoked via: `uvicorn api.main:app --reload --port 8000`
- Requires venv activation: `source .venv/bin/activate`

**Web entrypoint**: `web/index.html` served by FastAPI at `/`
- Static assets at `web/static/` mounted at `/static`
- Pure vanilla JS (no build step)

**Boot status**: Server starts and `/health` responds.

**Critical issues found**:

1. **Backtest engine is options-only** — `run_backtest()` in `backtest/engine.py` requires a predictions DataFrame with columns like `option_key`, `mid`, `expiry`, `type`, `strike`, `moneyness`, `oi`, `spread_pct`, `expiry_dte`. There is no underlying-only (buy & hold) strategy.

2. **Prediction data is ML-generated/synthetic** — The demo predictions parquet contains 924 rows of options data for AAPL (2025-07-25 to 2025-10-27) that were generated by the ML pipeline. This is NOT historical options quote data — it's model output over yfinance data.

3. **Backtest returns empty results** — When called with date range 2020-01-01 to 2020-12-31 against predictions that span 2025-07-25 to 2025-10-27, the date filter produces an empty DataFrame → empty equity curve → empty metrics `{}`.

4. **No buy & hold strategy** — The STRATEGIES dict only contains options strategies (straddle, credit_spread, covered_call). No underlying-only strategy exists.

5. **UI wiring assumes prediction-based workflow** — The backtest form requires selecting a "Predictions Run" before running a backtest. There's no way to run a simple underlying-price backtest from the UI.

6. **Heavy unused dependencies** — requirements.txt includes mongo, redis, celery, boto3, mlflow, dvc, torch — none of which are needed for the MVP.

7. **`pydantic_settings`** import in `api/core/settings.py` — uses `BaseSettings` from `pydantic_settings`, which is a separate package.

8. **Pydantic V1 deprecated `@validator`** used in `common/schema.py`.

### Assessment

The repo boots and `/health` works, but `/backtest` is a hallucination — it silently returns empty results because:
- The engine only supports options strategies
- The demo data doesn't cover the requested date ranges
- There's no validation that results are non-empty
- There's no underlying-data-only backtest path

### Phase 1 Plan — Golden Path MVP

**Goal**: Make `POST /backtest` work end-to-end with real underlying price data using a buy & hold strategy.

**Steps**:
1. Add `buy_and_hold` strategy that operates on underlying price data (OHLCV from yfinance)
2. Create a `DataProvider` abstraction that fetches/caches underlying price data
3. Modify `run_backtest()` to support underlying-only mode (no predictions DataFrame required)
4. Update `BacktestRequest`/`BacktestResponse` schemas to include summary metrics, equity curve, and trade list in the response
5. Update `POST /backtest` endpoint to return full results (not just bt_id)
6. Validate backtest output is non-empty; return 422 for invalid date ranges
7. No NaN values in JSON responses
8. Wire UI to call new backtest endpoint and render equity curve + summary
9. Write tests for: portfolio math, equity curve, metrics, API shape, determinism
10. Remove/disable options-only strategies (return 409 if options strategy requested)

**Architecture Decision**: The MVP will use yfinance to fetch daily OHLCV data for underlying equities. This is real market data. Options backtesting will be explicitly unsupported until a real historical options data provider is integrated.
